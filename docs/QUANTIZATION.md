# Quantization

Which weight formats the checkpoints use, at how many bits, and what that costs in perplexity.

## Formats

* **EXL3** (trellis): the `exl3` conversions of turboderp's exllamav3. `bits` is the average over the tensors; the head, the MTP head and the vision tower have their own widths. Loaded as they are, decoded in the GEMV / GEMM kernels.
* **NVFP4** (modelopt): E2M1 values with an E4M3 scale per 16 and one FP32 scale per matrix. Software-unpacked on Volta (no FP4 hardware). Either read from a modelopt checkpoint (the routed experts), or made at load by the engine's quantizer from BF16 tensors (round to nearest with a +-2 code search per block, or the calibrated tensors from `tests/tools/nvfp4_ldlq.py`). FP8 sources (the Flash-Next MTP experts: E4M3 with 128 x 128 block scales) are dequantized first.

## Volta tile order (EXL3)

A 16x16 weight tile is stored in the order of the Ampere `m16n8k16` fragments, so the Volta GEMM moves each lane's decoded values to the lanes that need them with shuffles. A checkpoint in the Volta order (`"tile_layout": "volta"` in its `quantization_config.json`) stores the tiles so that the eight values a lane decodes are exactly its `m8n8k4` operands, and the kernels use them without moving anything (two octets share each output block and their partial sums are added once per column).

* The order is a property of the checkpoint, read at load time and carried by every weight (`LinearWeight::volta_tiles`), so a target and its drafter may differ. SM_70 CUDA builds compile every translation unit whose kernels decode tiles twice, the second copy with `EXL3_VOLTA_LAYOUT=1` in namespace `exl3_vl` (`src/kernels/cuda/trellis/exl3_vl.cuh`): the GEMM kernels, the tensor-core and dp4a int8 GEMVs, `reconstruct`, the fused MoE decode tile (tensor-core and int8) and the persistent MoE kernel. The CPU and Vulkan builds read both orders in their reconstruction. ROCm builds and CUDA devices of SM_80 or later read the stock order only, and the loader refuses a Volta-order checkpoint there; the `cpu_experts` kernel reads the stock order only as well. `configs/glm_volta.json` is the GLM configuration with model and drafter in that order.
* `tests/tools/exl3_volta_layout.py <in> <out>` re-encodes a checkpoint (exllamav3 venv; `--claim` runs one process per GPU, `--max-layers N` cuts the model to its first N layers). Half-integer rates go through the fractional-rate quantizer of upstream exllamav3, built from its sources on first use (`tests/tools/exl3_frac_ext.cu`); the quantizer runs at about 16 thousand tiles per second per GPU at 2.5 bpw, so a whole GLM takes hours. The order is a tile permutation applied before the trellis encoder, which does not depend on it; re-encoding already quantized weights adds about one quantization's worth of error, so a conversion from the BF16 weights is the way to produce a real checkpoint.
* `tests/tools/exl3_quantize.py --src <bf16 dir> --template <exl3 dir> --out <dir> [--order volta|stock] [--hess map.json]` quantizes BF16 weights with upstream exllamav3's quantizer (regularization, global scale search, block-LDL error feedback, trellis encoder; integer and half-integer rates) in either tile order, so a Volta-order checkpoint made this way carries no re-encode error. Upstream's Python is loaded from `EXLLAMAV3_UPSTREAM_DIR` and the encoder it calls is built on first use from its sources (`tests/tools/exl3_quant_ext.cpp`, sm_70); only the tile permutation is replaced. The template is an existing EXL3 directory of the same model: it names the tensors to quantize, their rates and codebooks, and supplies everything that stays as it is. `--hess` maps tensor names (the Hessians come from `test_ppl --calibrate` with `ENGINE_HESSIAN_DIR`, or from a served run; sites per layer: 0 attention input, 1 MLP input, 2 o_proj / out_proj input, 3 down_proj input, (0, 4) the LM head input; `tests/tools/hess_merge.py` mixes capture directories with weights (agent sessions against prose), `qwen_hess_map.py` writes the map for a Qwen3.5-family dense model (the per-rank files of a row-parallel input form a block diagonal), `hess_check.py` validates a directory) (or `prefix*`) to Hessian files of the `ENGINE_HESSIAN_DIR` format; a tensor without one is quantized without calibration. `tests/tools/exl3_dequant_check.py` decodes a checkpoint in plain torch and prints the relative error against the BF16 weights.
* `test_trellis_order` decodes the same random codes in both orders (the Volta reconstruction must equal the permuted stock one bit for bit) and checks the GEMV, GEMM and reconstruct paths of each order against a double-precision product from 1 to 48 rows; `test_trellis_layout` checks the dequantizer against a golden decode (`tests/tools/trellis_layout_golden.py --layout stock|volta`); `test_prefill_linear` compares the fused GEMM and the GEMV with reconstruct plus the tensor-core GEMM from 1 to 64 rows; `test_moe` with `MOE_SYNTH=1` runs the MoE kernels on random experts of any widths in either order. `ENGINE_DEBUG_GLM_LAYERS=N` cuts the GLM to its first N layers, so a short `--max-layers N` conversion can be compared with the original through `diag_logits_dump` and `compare_logits.py`.

## Quantizing EXL3 with the engine

`volta_quantize --src <original> --template <EXL3 directory> --out <dir> [--hess <capture dir>] [--route <route dump>] [--order volta|stock] [--devices 0,1,2,3] [--only A,B] [--skip A,B] [--bits B] [--ranks 4] [--route-rows N] [--budget-mb 8192] [--seed N] [--no-scaled-hessian] [--affinity-eps E] [--ldl-metric] [--open-trellis] [--tile-gain] [--redo] [--plan] [--no-assemble]` quantizes a checkpoint on the GPUs with the engine's own EXL3 quantizer (`engine_quant`, `src/kernels/cuda/trellis/quant`: the algorithm of exllamav3 1.6.7's quantizer, MIT, with the trellis encoder ported to SM_70 and decoding through the inference codebook).

* **What is quantized.** The template is an EXL3 checkpoint of the same model: every tensor it stores as a trellis is quantized from the original at the template's width and codebook, everything else is copied as the template has it, and the output keeps the template's shards and file names. `--plan` lists what would be done without a GPU. The original's tensors are read as BF16, FP16, FP32 or FP8 E4M3 with block scales (`weight_scale_inv`), from fused experts (`experts.gate_up_proj`, `experts.down_proj`), and GLM's fused `qkv_proj` from `q_proj`, `k_proj` and `v_proj`; a tensor the original lacks or shapes differently (the vision tower's padded widths) stays as the template has it.
* **Hessians.** `--hess` is a capture directory of `test_ppl --calibrate` (`hessian_dir`), mapped to the tensors by the model's sites (Flash-Next, GLM, the Qwen3.5 family: see below); the row-parallel inputs' per-rank files form a block diagonal. A routed expert's down projection takes the Hessian of its own activation (the model's SwiGLU, with GLM's limit) over the rows of the route dump (`--route`, written by `route_dump`; `--route-rows` caps the rows per layer), computed per layer when its experts are quantized, so no Hessian files are written. `--affinity-eps E` weights the routed experts' Hessians by routing as exllamav3 1.6.7's `--moe_affinity_eps` does: a row counts with eps times the expert's mean routing weight plus its routing weight where it is routed to the expert, so each expert's gate and up projections get their own input Hessian (from the route dump's rows routed to it) and are quantized expert by expert; it needs the dump's routing weights (`<route dump>.w`, which `route_dump` writes next to it). A tensor without a Hessian is quantized without error feedback.
* **Per tensor.** The Hessian is damped (`--sigma-reg`, default 0.025 of the mean diagonal); the weight gets random output and input sign flips, per-channel output and input scales, the 128-point Hadamard rotation on both sides and a searched global scale (a coarse grid, then a fine one around its minimum; a projection after the first in a group, or a layer's next expert down projection, starts the fine grid at the previous one's scale and runs the coarse grid only when the minimum lands on an edge); its block LDL factor is that of the Hessian with its own input scales folded in (exllamav3 1.6.7's `scaled_hessian`; `--no-scaled-hessian`: one factor of the sign-flipped Hessian per input); the 16-row blocks are quantized from the last to the first with the LDL error feedback; two rounds refit the stored scales (`suh`, `svh`) to the quantized weight in the Hessian metric. `--ldl-metric` weights each element's squared error in the Viterbi search by its row's diagonal of the block's LDL metric. The reported proxy error is tr(E^T H E) / tr(W^T H W) of what is stored, with the damping taken out of H.
* **Work.** A work item is the projections of one input (every expert's gate and up projections share the block input), side by side in chunks of `--budget-mb`, which go through the encoder together block row by block row, or a layer's expert down projections; one thread per device in `--devices` takes items until none are left. Every finished tensor is written to `<out>/.partial`, so a run continues where it stopped (`--redo` quantizes again); the shards are written at the end (`--no-assemble` stops before them; a later run without it writes them from `.partial`).
* **Tile order.** `--order volta` (the default) writes `"tile_layout": "volta"`; from a stock template, the tensors that stay as the template has them are listed in `"tile_layout_stock"`. `--only` (tensors whose names contain any of the substrings) needs the template's order, and a Volta template's stock-order exceptions are kept as they are. `--bits` gives every quantized tensor one width (1 to 8, or 1.5, 2.5, 3.5 with mul1) instead of the template's, for rate ladders on a sample.
* **Extended trellis.** `--open-trellis` encodes each tile without the tail-biting ring and stores its start state, the bits before its stream, as `<base>.tstart` (uint16 per tile); `--tile-gain` stores a gain per tile as `<base>.tgain` (8 bits, the value (896 + c) / 1024, fitted by least squares before the error feedback sees the tile). A tensor's companions are its flag. Both options apply to the routed experts only: the engine's MoE kernels on CUDA decode them (the coop decode kernels on their tensor-core tile, the persistent prefill kernel at every row tile, both tile orders), and the loader reads them with whole expert tensors. Dense layers, the heavy-expert path (`moe_heavy_rows`), CPU and Vulkan experts, ROCm's coop kernels and sliced expert loads refuse an extended tensor. `reconstruct_slice_ext` and `reconstruct_had_slice_ext` decode them, and the tools read and write them; `hess_compare` scores `.partial` results that have them.

`hess_compare` compares calibration sources: `stats <dir_a> <dir_b>` sets the mean Hessians of two capture directories against each other per site; `cross --src <original> --tensor <name> --a <file> --b <file> [--bits 3]` quantizes a tensor with each of two Hessians and scores both results under both; `score --src <original> --tensors A,B (--hess-dir <capture dir> | --route <dump>) --exl3 <dir> ...` scores the tensors of EXL3 checkpoints against the original under one Hessian (the capture's, or a routed expert's activation Hessian over the route dump); a checkpoint may be a `volta_quantize` `<out>/.partial` directory, whose files carry their tile order and codebook, and `--affinity-eps E` scores the routed experts under their routing-weighted Hessians instead; `routes --src <original> --route <dump> --layers L,... [--top 32]` lists each layer's most-routed experts and their projections as a `--only` list; `moe --src <original> --route <dump> --layers L,... [--max-rows 8192] --exl3 <dir> ...` scores each routed expert of the first directory by its output's error against the original expert's over the dump's rows routed to it, each row weighted by its routing weight squared (its share of the MoE block's output), per layer and relative to the first directory.

End-to-end scale tuning (Flash-Next): `volta_e2e --model <EXL3 dir> --inputs <file> --teacher <file> --out <dir> [--devices 0,1,2,3] [--tp 1] [--fp16 1] [--norms 1] [--steps 64] [--batch 4] [--lr 1e-3] [--warmup 2] [--lr-min 0.1] [--hold 4] [--train N] [--eval-every 16]` tunes every EXL3 tensor's input and output scales (log deltas on the checkpoint's) and the norms' weights (additive deltas: the hyper-connection sites', attention's q / k norms, GDN's gated norm, PLE's; `--norms 0` keeps them; codes and the other dense weights frozen) by Adam on KL( teacher || model ) over token sequences, `--batch` sequences per step, the learning rate warming up linearly over `--warmup` steps and then following a cosine down to `--lr-min` of `--lr`. The model runs in FP32 training form (`engine/train/qwen4_exp.h`), each layer recomputed from its saved input in the backward (its sublayer outputs kept from the forward). With `--tp 1` the devices run it tensor parallel over NCCL, one host thread each: every device holds all layers, the per-position work on its block of the sequence's rows, GDN and attention by heads, the routed experts by expert, the head by vocabulary; `--tp 0` splits the layers over the devices instead. The routed experts of a layer run in groups of similar route counts, each group's cores decoded together and its products one strided batch. The tuned tensors' products run on the tensor cores (`--fp16 1`, the default): the decoded cores in FP16 (exact: the trellis decodes to FP16), activations and gradients rounded to FP16 per row at a power-of-two scale, FP32 accumulation; norms, recurrences, attention, the scale gradients' sums and Adam stay FP32. `--fp16 0` runs those products in FP32. The model's own inputs come from `test_ppl --flash --calibrate --file TEXT --seq S --tokens N --chunk 512` with `train_inputs` set (its token embeddings and the PLE layer's n-gram rows), the teacher from the reference model on the same text (`test_ppl --flash --file TEXT --seq S --tokens N --chunk 16 --topk-out FILE`: the top K tokens of every position and the mass outside them). The last `--hold` sequences are held out (`--train N` trains on the first N of the others only); the values of the best held-out KL are written as a new checkpoint (the input's files, its shards with the tuned scales and norm weights in FP16, the precision the engine computes them in). `test_ppl --kl-teacher FILE` measures any checkpoint's KL against such a teacher through the inference path.

Agent sessions as calibration text: `volta_sessions --out <dir> [--max-chars 120000] SESSION.jsonl ...` turns recorded Claude Code sessions into Anthropic Messages request bodies (main-thread turns in order, consecutive entries of one role joined, thinking, tool calls and tool results as recorded, cut at a message boundary past `--max-chars`). Posted to a server's `/v1/messages/count_tokens` with `dump_requests` set, each is rendered by the model's chat template exactly as the live conversation was, without a forward pass, and written as `req_N.prompt.txt`; `test_ppl --calibrate --prompts <dir>` captures Hessians (and with `route_dump` the route rows) from them. `--route` of `volta_quantize`, `volta_tune` and `hess_compare` takes several dumps comma-separated (their rows in that order), and `hess_compare merge <out> <dir> <dir> ...` sums the capture files of several directories, so captures of different kinds of text form one calibration, mixed by their token counts. Answers of another server (a hosted copy of the model) become calibration text the same way: `volta_sessions --requests PROMPTS.json --out <dir> --model NAME [--max-tokens 6000] [--temperature 1.0] [--top-p 0.95]` writes chat completion bodies for a prompt list (`test_ear`'s format), and `--conversations PROMPTS.json --responses <dir> --out <dir>` turns the replies into Anthropic bodies of the exchange, the reasoning as a thinking block (a reply cut inside its reasoning keeps the reasoning alone). `test_ear --generate --text-out <dir>` writes the local model's own answers as `sN.prompt.txt` for `test_ppl --calibrate --prompts`.

`volta_tune --src <original> --exl3 <dir> --route <dump> --out <dir> --layers L,... [--steps 100] [--lr 0.001] [--max-rows 8192] [--devices 0,1,2,3]` tunes the scale vectors of routed experts (gate, up and down `suh` / `svh`, multiplicatively, with Adam) so that the quantized expert's output matches the original's over the dump's rows routed to it (weighted as in `hess_compare moe`), keeping the step with the lowest error on every tenth row, which is held out; the trellis cores stay as they are, and the results go to `<out>/.partial` in `volta_quantize`'s per-tensor form. `--route-q <dump>` switches to block tuning: the dump is of the same text through the quantized model, so its rows carry the error of every layer before; all of a layer's experts are tuned together so that the quantized routed MoE output on those rows (the quantized model's routing) matches the original's on the reference rows of `--route` (the reference routing), in batches of `--batch` tokens, every tenth token held out for the step choice; `--eval-ref` / `--eval-q`, a reference and a quantized dump of held-out text, report the block error there before and after. It is built on the engine's training primitives (`engine_train`, `inc/engine/train/grad.h`: SwiGLU forward and backward, a linear given as a core between per-channel scales with its scale and input gradients, a row-weighted squared-error loss, Adam). `test_exl3_encode` and `test_exl3_quantize` test the encoder and the quantizer ([TESTS.md](TESTS.md)).

Flash-Next's 6.05 bpw checkpoints (6-bit experts) run their prefill on the persistent MoE kernel's uniform 6-bit instantiation (gate, up and down of one width).

## Quantizing EXL3 from the original weights

For a Qwen3.5-family dense model (tile order stock or Volta), with a model of the same architecture already quantized to EXL3 as the template:

1. **Calibration text.** Serve a model with `--set dump_requests=<dir>` and run `tests/agentic/bench.py` against it (`gen_tasks.py` generates the tasks); `tests/tools/prose_corpus.py` writes plain prose from book transcripts.
2. **Hessians.** `ENGINE_HESSIAN_DIR=<dir> ENGINE_HESSIAN_LAYERS=<lo-hi> test_ppl --calibrate --prompts <dump dir> --select train --tokens N --chunk 512` replays the sessions (rows shared between sessions count once) and `--file prose.txt --seq 2048` the prose, in slices of layers that fit beside the weights (16 layers per pass at tensor parallel 2). Each capture directory takes about 0.9 GB per layer.
3. **Mix and map.** `hess_merge.py --src agent_dir:0.7 --src prose_dir:0.3 --out mix_dir`, `hess_check.py` on the directories, `qwen_hess_map.py --dir mix_dir --out map.json --layers 64 --ranks 2`.
4. **Quantize.** `exl3_quantize.py --src <original weights> --template <EXL3 directory> --out <dir> --order stock|volta --hess map.json --skip model.visual`; a shard that already exists in `--out` is skipped and a restarted shard continues from the tensors it finished.
5. **Score.** `test_ppl --prompts <dump dir> --select hold --sessions 10` gives the perplexity of the assistant turns of held-out sessions (system and user text carry no meaningful loss for a chat model, so only the model's own turns are scored).

Flash-Next (`qwen4_exp`) follows the same steps with `test_ppl --flash --calibrate` (all ranks), `flash_hess_map.py` for the map and `--passthrough` for the tensors the template does not quantize. The routed experts' gate and up projections share the block-input Hessian (every expert sees every row); their down projections need each expert's own intermediate activations, which `moe_down_hessians.py` computes from the router-input rows that `route_dump` (`ENGINE_DEBUG_ROUTE_DUMP`) records. The MTP head is captured with `ENGINE_CALIB_MTP=1` on the same replays: the head runs after every forward on the same rows, and its sites are written as layer 48 (the block: the same five sites as a decoder layer) and layer 49 (site 0 = `fc_embedding` input, site 1 = `fc_hidden` input); `route_dump_from=48` limits the route dump to the head's block and `moe_down_hessians.py --layers 48-48 --prefix mtp.layers --src-offset 48` gives its experts' down-projection Hessians. A DFlash2 drafter is captured while the server speculates (`--set dflash_hessian_dir=<dir>` with `speculator=dflash`; files `L<layer>_s<site>_r<rank>.f32`: site 0 `q_proj`, 1 `k_proj` / `v_proj` (context and block rows), 2 `o_proj` and 4 `down_proj` per rank, 3 `gate_proj` / `up_proj`; layer 5 site 0 is the `fc` input), written when the server shuts down.

GLM-5.3-Flash (`glm5_next`) is captured with `ENGINE_EXPERT_CACHE=0.95 ENGINE_MAX_SEQ=32768 ENGINE_MAX_SLOTS=1 ENGINE_HESSIAN_DIR=<dir> ENGINE_HESSIAN_LAYERS=<lo>-<hi> test_ppl --glm --calibrate --prompts <dump dir> --select train` in slices of layers (15 per pass fit; a capture keeps the dense MLPs and the shared expert unsliced, which is why the experts are not all resident). Sites per layer: 0 attention input, 1 FFN input, 2 `o_proj` input (one file per rank), 3 the shared expert's down input (layers 0 to 2: the dense MLP's 12288-wide down input), 4 the q-lora norm output (MLA layers: `q_b_proj` and `indexer.wq_b`), and layer 0 site 5 the `lm_head` input; the replicated sites live on rank `layer % tp` and are written as `_r0`. The replay restores a snapshot of the prefix that a family of sessions shares (their system prompt) instead of running it again, so a session costs about its own new tokens. `glm_route_split.py` splits a `route_dump` into one file per layer, `moe_down_glm.py` computes the experts' down-projection Hessians from those rows and the original's FP8 weights (block scales, the model's swiglu limit), `glm_hess_map.py` writes the map with the template's tensor names, and `exl3_quantize.py` builds the fused `qkv_proj` of the linear-attention layers from the original's `q_proj`, `k_proj` and `v_proj` (rows in that order). The expert Hessians of 288 experts per layer do not fit on disk at once; they are written for the experts of one shard just before that shard is quantized and deleted after it.

A checkpoint names its tile order in `quantization_config.json` (`"tile_layout": "volta"`; no entry means the stock order). The order is not visible in the tensors themselves (the other order decodes to noise without any error), so the entry has to be right. The weights the quantizer skipped (`--skip model.visual`: the vision tower, whose widths are not multiples of 128) keep the template's stock order, so `exl3_quantize.py --order volta` writes their name substrings as `"tile_layout_stock": ["model.visual"]` next to the layout entry (when the template itself is stock), and the loader reads the weights those match in the stock order; without the entry such a tower decodes as noise (its embeddings are garbage and the model answers a picture's question without seeing it). `exl3_quantize.py` takes FP8 (block scales), compressed-tensors NVFP4 and modelopt NVFP4 sources, and `--nvfp4-roundtrip` passes BF16 weights through NVFP4 rounding first.
