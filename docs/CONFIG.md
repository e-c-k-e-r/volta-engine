# Configuration

Generated by `volta_server --print-config-docs`; do not edit by hand (the static gate checks that this file is current).

A launch is configured by a JSON file (`--config file.json`) and command-line flags; flags win over the file, the file wins
over environment variables, environment variables win over built-in defaults. Unknown keys, unknown options and invalid
values are fatal errors. The model type is never configured: it is read from the checkpoint's `config.json`.

## Launch config keys (top level of the JSON file)

| Key | CLI flag | Default | Description |
|---|---|---|---|
| `model_dir` | `--model-dir` | required | checkpoint directory |
| `draft_model_dir` | `--draft-model-dir` | none | DFlash2 drafter checkpoint; required with `use_speculation` |
| `use_speculation` | `--speculative` | false | enable speculative decoding |
| `tp_size` | `--tp-size` | 4 | GPUs (1, 2 or 4; GLM runs on 1, 2 or 4) |
| `host`, `port` | `--host`, `--port` | 0.0.0.0, 8000 | listen address |
| `max_batch_size` | `--max-batch-size` | 8 | concurrent decode slots the scheduler may fill (capped by `max_slots`) |
| `default_max_tokens` | `--max-tokens` | 256 | `max_tokens` for requests that omit it |
| `default_temperature`, `default_top_p`, `default_top_k` | `--temperature` | from the checkpoint's `generation_config.json` | sampling defaults for requests that omit them |
| `default_enable_thinking` | | false | thinking on for requests that do not say |
| `request_timeout_s` | | 30 | seconds a connection may stay silent before its request is complete |
| `video` | see below | | MiniMax-H3 settings |
| `options` | `--set key=value` | | the options below |

## MiniMax-H3 (video and audio generation)

A `model_dir` that is a MiniMax-H3 pipeline directory (it holds `model_index.json`; the FL2VA or Ref2VA component directory with `text_encoder`, `video_vae`,
`audio_vae`, `tokenizer`) starts the generation service instead of the language-model runtime: a job queue with one worker that owns the GPUs, the job API
(`/api/jobs`, `/api/info`) and a web page at `/`. `tp_size` is the number of GPUs the transformer is split over unless `devices` is given.

| `video` key | CLI flag | Default | Description |
|---|---|---|---|
| `dit` | `--dit` | required | INT8 ConvRot transformer checkpoint of the FL2VA partition (text and keyframe tasks) |
| `dit_ref2va` | `--dit-ref2va` | none | the Ref2VA partition; enables reference images, videos and audio |
| `lora_dirs` | `--lora-dir` (repeatable) | none | directories scanned for adapters (turbo and community LoRAs) |
| `out_dir` | `--out-dir` | `h3_jobs` | job history and results |
| `devices` | `--devices 0,1,2,3` | the first `tp_size` GPUs | GPUs of the transformer |
| `max_rows` | `--max-rows` | 36000 | largest packed sequence one job may need (a resident transformer is sized for it) |
| `resident` | `--resident` / `--no-resident` | true | keep the transformer (weights and adapters, on every GPU) loaded between jobs; off loads it for each job and frees it after (about 10 to 15 s slower per job, for machines that share the GPUs). The VAEs, the image encoder and the language-model stack are always loaded per stage: next to the transformer the first GPU has room for one at a time |
| `resident_idle_s` | `--resident-idle-s` | 0 | with `resident`: free the transformer after this many idle seconds (0 = never) |
| `resident_decoders` | `--resident-decoders` / `--no-resident-decoders` | true | with `resident` and `tensor_parallel`: keep the video decoders and the audio VAE loaded between jobs too (about 6 GB per GPU; saves the 3.6 s decoder load of every job). Ignored with sequence parallelism, where the full-weight transformer leaves no room |
| `text_encoder` | `--text-encoder` | none | directory of an EXL3 conversion of the Qwen3-VL-32B-Instruct language model (e.g. `turboderp/Qwen3-VL-32B-Instruct-exl3`): its 50 layers stay resident, sharded over `devices` (about 4.6 GB per GPU at 6 bpw on four), instead of streaming 49 GB of BF16 per job; the text stage of a short prompt drops from about 7 s to under a second. The vision tower still loads from the model directory. Use it with `tensor_parallel`: next to the full-weight sequence-parallel transformer it does not fit in 32 GB |
| `captioner` | `--captioner` / `--no-captioner` | false | the resident text tower also writes text: the page's Caption button has the Qwen3-VL language model describe a reference image as a video prompt (the prompt box, if filled, steers it). Loads the last 14 layers, the LM head and a KV cache: about 1.3 GB more per GPU on four (1.9 GB on the first, which holds the head); needs `text_encoder` with all 64 layers (an EXL3 conversion) |
| `tensor_parallel` | `--tensor-parallel` / `--no-tensor-parallel` | false | shard the transformer over `devices` by attention heads and MLP width (a quarter of the weights and of the activations per GPU, so the VAEs and the language model fit next to it) instead of by rows; about 1 s slower per step, needs a build with NCCL; text prompts up to about 8.6K tokens |

## Options

Every option can be set in the launch config's `options` object, with `--set key=value`, or through the environment variable
shown. Debug options use `ENGINE_DEBUG_<NAME>`. Test-only variables are listed at the end.

| Option | Type | Default | Environment | Description |
|---|---|---|---|---|
| `log_level` | string | `info` | `ENGINE_LOG_LEVEL` | log threshold: error, warn, info or debug |
| `tp` | int | `-1` | `ENGINE_TP` | rank count: 1, 2 or 4 (GLM: 1, 2 or 4; the CPU build runs one rank, the Vulkan build one device per rank); <0 uses the launch's tp_size |
| `arena_gib` | int | `-1` | `ENGINE_ARENA_GIB` | per-GPU arena in GiB; <=0 sizes it from the device's free memory minus vram_reserve_mib |
| `vram_reserve_mib` | int | `-1` | `ENGINE_VRAM_RESERVE_MIB` | memory left outside the arena for graphs, workspaces and the CUDA context; <0 uses the model's default (Qwen 1536, GLM 288) |
| `max_seq` | int | `0` | `ENGINE_MAX_SEQ` | context window per slot in tokens (sizes the KV pool); 0 = the model default (Qwen 32768, GLM 12288) |
| `max_slots` | int | `0` | `ENGINE_MAX_SLOTS` | decode slots; 0 = the model default (Qwen 8, GLM 1) |
| `prefix_cache_gib` | int | `16` | `ENGINE_PREFIX_CACHE_GIB` | pinned host RAM for the prefix cache (sequence snapshots); 0 = off |
| `prefill_chunk` | int | `512` | `ENGINE_PREFILL_CHUNK` | prompt tokens a new request prefills per scheduler step while other requests are decoding (decode steps run between the pieces); 0 = the whole prompt at once |
| `prefix_interval` | int | `16384` | `ENGINE_PREFIX_INTERVAL` | prompt tokens between automatic prefix checkpoints inside long prompts; 0 = only the requested ones |
| `nvfp4_experts` | string | `(empty)` | `ENGINE_NVFP4_EXPERTS` | Flash-Next: directory of a modelopt NVFP4 checkpoint (same architecture) to load the routed experts from; everything else comes from the model directory. Empty = the model's own experts |
| `nvfp4_dense` | string | `(empty)` | `ENGINE_NVFP4_DENSE` | dense projection groups to quantize to NVFP4 at load (round-to-nearest from the BF16 tensors of the nvfp4_experts checkpoint): Flash-Next: gdn, shared (or shared_gate / shared_up / shared_down), attn, idx, head; GLM: kda, mla, idx, shared, dense, head; Qwen NVFP4 checkpoint: head (a quarter of the bytes of the FP16 head); or all |
| `hessian_dir` | string | `(empty)` | `ENGINE_HESSIAN_DIR` | Flash-Next calibration: directory to write the input Hessians (x^T x per dense projection input, fp32) of the prefill rows that ran, one file per site at shutdown; empty = off |
| `mtp_nvfp4` | bool | `false` | `ENGINE_MTP_NVFP4` | Flash-Next: load the MTP head from the nvfp4_experts checkpoint instead of the model directory (its FP8 block-scaled experts and BF16 dense tensors are quantized to NVFP4 at load; the head then matches the base model, not the model directory's conversion) |
| `nvfp4_dense_dir` | string | `(empty)` | `ENGINE_NVFP4_DENSE_DIR` | Flash-Next: directory of calibrated NVFP4 dense tensors (tests/tools/nvfp4_ldlq.py) used instead of round-to-nearest for the groups of nvfp4_dense they cover |
| `nvfp4_dense_src` | string | `(empty)` | `ENGINE_NVFP4_DENSE_SRC` | directory of a modelopt NVFP4 checkpoint of the model whose BF16 dense tensors the nvfp4_dense groups are quantized from (GLM; Flash-Next takes them from nvfp4_experts) |
| `hessian_layers` | string | `(empty)` | `ENGINE_HESSIAN_LAYERS` | with hessian_dir: layers to collect, "lo-hi" (GLM: the accumulators of all 45 layers do not fit beside the weights, so collect a third at a time); empty = all |
| `kv_format` | string | `(empty)` | `ENGINE_KV_FORMAT` | KV cache format: fp16, fp8, k8v4 or nvfp4; empty = the model default (fp16). GLM stores its single latent tensor in one format (k8v4 = 8-bit) |
| `kv_pool` | int | `0` | `ENGINE_KV_POOL` | GLM: tokens of one shared KV pool for all slots (latent cache and indexer keys, in pages of 512 tokens); 0 = every slot owns max_seq tokens. With 2 slots of 256K, 262144 holds one long and one short conversation, or two of 128K, in half the memory; a request is admitted when the pool has room for its prompt and ends with finish reason length when the pool runs out |
| `expert_cache` | float | `1` | `ENGINE_EXPERT_CACHE` | resident routed-expert fraction in (0, 1] (GLM, Flash-Next); 0 = GLM only: the largest fraction the arena holds after the other weights, the speculator and a 0.25 GiB margin (the log prints the plan); below 1 enables the two-tier expert cache: the codes of the cold experts live in pinned host memory and are read over PCIe |
| `expert_stage` | bool | `true` | `ENGINE_EXPERT_STAGE` | expert tier, prefill chunks: copy a layer's cold experts once into device scratch, a layer ahead of the compute, instead of reading them over PCIe from every row tile (needs 2 x the cold experts of a layer in the arena; off when it does not fit) |
| `expert_adapt_every` | int | `64` | `ENGINE_EXPERT_ADAPT_EVERY` | decode steps between expert residency rebalances (0 = never) |
| `expert_swap_margin` | int | `2` | `ENGINE_EXPERT_SWAP_MARGIN` | a cold expert replaces the coldest resident one only when its decayed route score exceeds 1.5 x the resident one's plus this margin (scores are route counts per rebalance window, folded as score / 2 + count); lower values adapt faster and flip more |
| `expert_history_pct` | int | `75` | `ENGINE_EXPERT_HISTORY_PCT` | the largest share (percent) of a swap decision taken from a layer's long-run route counts (saved between runs with expert_heat_file) instead of the last windows; it grows with the amount of history, so a cold start follows the first windows; 0 = windows only |
| `expert_swaps` | int | `-1` | `ENGINE_EXPERT_SWAPS` | maximum expert swaps per layer per rebalance; <0 = derived from expert_swap_mib |
| `expert_swap_mib` | int | `1024` | `ENGINE_EXPERT_SWAP_MIB` | bytes the swaps of one rebalance pass may move (MiB; a swap moves two experts), spread over the layers, when expert_swaps is not set |
| `expert_heat_file` | string | `(empty)` | `ENGINE_EXPERT_HEAT_FILE` | file the tiered experts' per-layer route counts are saved to (every few rebalances and at exit) and read from at start: the resident sets then start with the hottest experts instead of experts 0..N-1 (one file per rank: .r<rank> is appended with more than one rank) |
| `speculator` | string | `dflash` | `ENGINE_SPECULATOR` | speculation source: dflash (needs a draft model) or mtp (the checkpoint's own multi-token-prediction head, Qwen) |
| `mtp_depth` | int | `7` | `ENGINE_MTP_DEPTH` | most draft tokens per round with speculator=mtp (1 to 7); the head stops chaining earlier when its recent accuracy is low |
| `draft_tp` | bool | `true` | `ENGINE_DRAFT_TP` | false runs the drafter on rank 0 only |
| `dsa` | bool | `true` | `ENGINE_DSA` | GLM sparse attention indexer (top-2048 key selection); false attends densely |
| `max_image_tokens` | int | `1024` | `ENGINE_MAX_IMAGE_TOKENS` | largest image the vision tower accepts, in language-model tokens (4 patches each; sizes its scratch and caps the resize); 0 = image input off |
| `expert_stats` | bool | `true` | `ENGINE_EXPERT_STATS` | count the routes per expert for the monitor page (a device sync per rank about once a second while serving) |
| `spec_ctrl` | bool | `true` | `ENGINE_SPEC_CTRL` | adaptive speculation controller; false always speculates |
| **Debug** | | | | |
| `moe_prefill_tile` | bool | `true` | `ENGINE_DEBUG_MOE_PREFILL_TILE` | trellis MoE, prefill chunks of more than 128 rows: the 32-row expert tile with two resident blocks per SM; false runs the 16-row tile of the decode kernels (A/B) |
| `moe_gemv` | bool | `false` | `ENGINE_DEBUG_MOE_GEMV` | ROCm: the expert-grouped EXL3 MoE runs its projections on the v_dot2 GEMV instead of the WMMA kernels |
